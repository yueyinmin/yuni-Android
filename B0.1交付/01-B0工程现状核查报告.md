## 2. 必须区分的四种状态

### 已经实现
- 单模块工程、Gradle 工具链、Compose + Material 3 页面骨架。
- Room 本地库 v1、11 张表、DAO、Repository 接口与实现。
- Outbox 队列、同步协调器、WorkManager 周期任务、冲突处理。
- CloudBase HTTP 网关封装（REST / Auth / Functions）与本地离线替身。
- Android Keystore 加密的 TokenVault；SafeLog 只打长度和脱敏 ID，不打正文。
- ConflictResolver 的 5 个单元测试。

### 部分实现
- **双人空间**：有 `couple_profile` 表和本地创建方法，但邀请码核销是 `NotConfigured` 占位，云端云函数未部署。
- **同步**：有队列和协调器，但缺少按空间隔离的数据归属字段（`coupleId` 只存在于云端 payload，不在多数本地表里）。
- **隐私**：PRIVATE / SHARED 有枚举，但没有落到"能不能入队"的强校验；SERVER_CONTROLLED 只有设计描述，没有代码约束。
- **导航**：有 5 个平级 Tab，但不符合 K3 的 `首页/回忆/互动/信箱/我们`；缺少互动页、信箱页；日记和愿望占用一级 Tab。

### 尚未实现
- 账号注册/登录、邀请码、空间正式创建（B1 范围，本轮禁止开发）。
- 图片上传与相册、每日问答业务逻辑、未来信解锁、悄悄话收发、数据导出。
- 任何 B1～B7 业务页面。

### 存在问题（本轮必须修）
1. `AppConfig.kt`、`SafeLog.kt` 在 `core/` 根，`TokenVault.kt` 在 `data/auth/`，与分层目标不一致。
2. `YuniViewModel` 直接调 Room DAO，破坏 UI → Repository 边界。
3. 导航是 5 个平级 Tab，不符合 K3；缺互动、信箱入口。
4. `daily_question`、`letter` 没有 `coupleId`，无法按空间隔离；`letter` 没有草稿正文和状态；没有消息表。
5. `diary` 没有 `coupleId`，共享日记无法判断属于哪个空间。
6. 无 Migration、无 schema 导出、无迁移测试——后续改表会直接面临"清库还是丢数据"的选择。
7. Outbox 的 `insertOrReplace` 每次生成新 UUID，实际上覆盖不了旧任务。
8. 无导航测试、无入队闸门测试。

### 本轮需要修改
上表 1～8 项，以及按工单要求补齐 11 份交付材料、Git 基线、产品规划书 V1.1。

### 本轮不应修改
- 任何 B1～B7 业务功能（注册、登录、邀请、空间创建、图片、问答、信件、悄悄话收发）。
- 技术栈（不换框架、不拆 Gradle 模块、不引入 Hilt）。
- 已有业务语义（日记仍分私密/共同，愿望仍是清单，退出登录不清本地数据）。
