# 06 — 隐私与安全边界规范

- 工单：US-B0.1-ARCH-ALIGNMENT / T06
- 性质：**规范 + 后续阶段测试清单**。本轮只建立规范和能落地的客户端闸门，不提前实现 B1～B6 的服务端安全测试。
- 原则：客户端的校验只提升体验，**服务端才是权限的最终裁判**。

---

## 1. 三级数据分类（保留规划书原定义）

### PRIVATE — 私密数据
- 原则：默认仅本人访问；另一成员不能直接读取；不因加入双人空间而自动共享；不默认上云；导出时要加密保护。
- 当前对应：`diary.visibility = 'PRIVATE'`；`localDraftContent`（信件草稿）；`TokenVault` 里的登录态。
- 已落地的客户端闸门：
  - `DiaryRepositoryImpl.add/update`：`syncable` 要求 `visibility == SHARED`，PRIVATE 直接为 false。
  - `OutboxWriter.enqueueDiary`：第一道闸门，非 SHARED 直接 return。
  - `DiaryDao.pendingUploadShared`：SQL 再兜一层 `visibility = 'SHARED'`。
  - `SafeLog` 没有打印正文或 token 的方法，只有 `eLength()`（只打长度）和 `mask()`（头尾各留 4 位）。
  - `TokenVault` 用 Android Keystore AES/GCM，`setUserAuthenticationRequired(false)` 只为后台同步可用；`clear()` 只清 prefs，不动业务数据库。
- 尚未落地：导出加密（B7）；"另一成员直接读取"的真实越权测试（B4 起）。

### SHARED — 双人共享数据
- 原则：必须属于明确的双人空间；只有该空间有效成员能访问；**必须检查空间 ID + 成员身份**；防跨空间。
- 当前对应：`memory`、`diary(SHARED)`、`wish`、`meeting_plan`、`daily_question`、`message`、`letter` 的 `coupleId`。
- 已落地的客户端闸门：
  - v2 所有共享表都有 `coupleId`（可空）。历史数据为 NULL = 待认领，不猜。
  - `OutboxWriter.enqueueDiary` 第二道闸门：`coupleId` 空/空白不入队；payload 写入 `couple_id`。
  - `DiaryDao.pendingUploadShared`、`MessageDao.pendingUpload` 都过滤 `coupleId IS NOT NULL`。
  - `DiaryRepositoryImpl.update` 使用 `existing.coupleId`，不允许通过改模型把数据搬到别的空间。
  - 每日问答唯一索引改 `(coupleId, questionEpochDay)`，两个空间同一天不冲突。
  - `CloudBaseMemoryRemoteDataSource.uploadMemory` 取 `CloudSessionState.coupleId`，为空直接返回 `NotConfigured("还没有共同空间，无法上传")`。
- 服务端必须做（B1 起）：RLS `is_couple_member(couple_id)`；所有写接口校验成员身份。客户端传错 coupleId 只能得到空结果或 403，不能靠客户端自觉。

### SERVER_CONTROLLED — 服务端控制数据
- 范围：邀请码核销、每日问答揭晓、未来信解锁、图片授权、空间解散。
- 原则：客户端不能通过改本地状态绕过限制。
- 当前状态：**全部是设计约束，未部署服务端**。代码里只有占位：
  - `CloudBaseCoupleRemoteDataSource.createInvite()` / `acceptInvite()` → `RemoteResult.NotConfigured("需要云函数 couple.issueInvite/redeem，B0 未部署")`。
  - `DailyQuestionEntity.partnerAnswer` 本地读取时被 SQL 滤掉，但真正的下发控制必须靠云函数。
  - `MailboxScreen` 文案明确写"解锁判定在服务端"，不假装本地能解锁。
- 要求：以上 5 类操作的最终判定必须在云函数 / 数据库策略里，不能放在 APK 里。

## 2. 客户端 / 服务端责任分界

| 动作 | 客户端可以做 | 服务端**必须**做 |
|---|---|---|
| 判断 PRIVATE 日记是否入队 | 可以，且已经做了 | 仍要拒绝任何 PRIVATE 内容的写入请求 |
| 决定 coupleId | 只能填，不能授权 | 用 JWT 校验 `is_couple_member(couple_id)` |
| 判断问答是否揭晓 | 只能不显示 | 未到点不下发 `partnerAnswer` |
| 判断信件是否解锁 | 只能显示状态 | 未到点不下发密文正文 |
| 生成图片链接 | 只能请求 | 签发短期授权 URL，禁止永久公开链接 |
| 核销邀请码 | 不能 | 云函数原子核销 + 防重复使用 |
| 解散空间 | 只能发请求 | 云函数校验成员身份并撤销授权 |

## 3. 八个攻击面 → 后续阶段验收清单

| # | 攻击面 | 风险 | 服务端防线 | 客户端辅助 | 纳入阶段 | 本轮状态 |
|---|---|---|---|---|---|---|
| 1 | 伪造 userId | 冒充他人读写 | JWT 验签，`auth.uid()` 取值，忽略客户端传的 user_id | TokenVault 不落明文 | B1 | 待实施 |
| 2 | 伪造 coupleId | 把数据挂到别人空间 | RLS `is_couple_member(couple_id)` | payload 写 couple_id，入队校验非空 | B1 | 客户端闸门已完成，服务端待实施 |
| 3 | 跨空间访问 | 读到别人两人的数据 | 所有查询带 couple_id 且走 RLS | DAO 按 coupleId 过滤 | B1 / B3 | 待实施 |
| 4 | 越权读取私密日记 | 另一成员看到 PRIVATE | 云端根本不存 PRIVATE；只存 SHARED 表 | Outbox 双闸门 + DAO 双过滤 | B4 | 客户端闸门已完成 |
| 5 | 提前读取问答答案 | 未揭晓看到对方答案 | 云函数按时间控制下发 | SQL `CASE WHEN revealed=1` | B5 | 客户端读取层已完成，服务端待实施 |
| 6 | 提前读取信件正文 | 未解锁看到密文 | 云函数按 unlockAt 下发；密钥不在客户端 | 本地表不存正式正文 | B6 | 待实施 |
| 7 | 获取永久图片链接 | 链接被转发长期有效 | 短期签名 URL + 权限校验 | 不缓存永久 URL | B3 | 待实施 |
| 8 | 邀请码重复核销 | 一人码多人用 | 云函数原子更新 + 唯一约束 + 单次使用 | 客户端不保存明文码 | B1 | 待实施 |

**规则**：每个对应阶段把上表相关行写进该阶段验收标准，不能只做功能验收。
